# Исследование скорости итераций Studio

Дата: 2026-10-18. Исходный Studio HEAD: `b73a8ef18`. Это исследование текущего
кода и локальных измерений; предложения ниже еще не являются реализацией.

## Вывод

Инкрементальная нативная сборка на измеренном стенде работает быстро. Оснований
переделывать кеш, добавлять еще один watcher или делать web основным циклом нет.
Найдены конкретный дефект deadline в DevAPI-клиенте, разница между поколениями
игровых инструментов и препятствие возобновлению части старых игр: несовпадение
закрепленных зависимостей. У локализации подтверждена лишняя перекомпиляция
потребителей заголовка из-за комментариев с переводами; ее стоимость пока мала
на измеренном стенде.

Первые действия по результатам исследования: исправить deadline подключения,
довести уже существующий focused-test путь до нужных старых потребителей и
явно показывать совместимость окружения выбранной игры. Массовый перенос
инструментов и переделка системы данных пока не обоснованы.

## Покрытие и метод

- Изучены текущие CLI, CMake, runtime/capture helpers, существующие разборы и
  ограниченные выборки истории 11 основных игр и 3 производных рабочих копий.
  Исторические записи перепроверены по текущим исходникам.
- Штатный `doctor` выполнен для всех 14 разных рабочих копий. Имена, пути,
  командные строки и соответствие анонимных обозначений играм остаются в
  игнорируемом `tmp/studio-refresh/native-research/doctor-runs.json`.

  циклов build → новый процесс → DevAPI readiness → точное сравнение C/schema
  маркеров → проверки консистентности. Последний цикл также сохранил скриншот.
- На двух реальных играх выполнены по три штатных `test --only`: первый прогон
  отделен от двух повторных. Один потребитель самостоятельный со своим деревом
  зависимостей, второй использует Studio и более новую нативную обвязку.
- Проведено 6 чередующихся запусков для проверки причины задержки DevAPI:
  3 текущих и 3 с изолированным прототипом ограниченного connect deadline.
- Отдельно измерены этапы полного native-capture preflight/final validation.
  Запись видео, web, portal и мобильные устройства в этом исследовании не
  запускались. Полный Studio gate повторно не запускался.
- Прочитан свежий профиль за 7 дней. Его категории и суммы интерпретируются
  как наблюдения инструментария, а не как время человеческого труда.

Среда: Windows 11 AMD64, Python 3.12.4, CMake 3.31.6, Ninja 1.12.1,
Clang 19.1.7, существующий Debug/DevAPI build. Это локальная рабочая машина,
не контролируемый лабораторный стенд. Выборки малы, кеши прогреты; системная
нагрузка и защитное ПО не изолированы. Числа не являются SLA или обещанием для
каждой игры. Обычные фоновые агенты в это время читали исходники; тяжелые
исследовательские сборки выполнялись последовательно.

Пробные изменения C, схемы и локализации делались только в общем стенде,
с резервной копией, проверкой отсутствия конкурентной правки и восстановлением
исходных байтов в `finally`. После восстановления выполнены обратные сборки и
проверка исходных runtime-маркеров. Движок не менялся. Состояние игры запускалось
с `--fresh-state --disable-autosave`; исследование не меняло пользовательские
сохранения. Прототип подключения находится только в игнорируемом временном
скрипте и не установлен в Studio.

## 1. Что реально стоит нативная сборка

Все строки ниже относятся к feature consumer. `Build` включает генерацию,
компиляцию и линковку, когда они потребовались. `Цикл` дополнительно включает
guard, metadata, запуск, semantic proof, проверки артефактов и завершение процесса.

| Проба | Build, мс | До DevAPI readiness, мс | Полный цикл, мс |
| --- | ---: | ---: | ---: |
| Без изменений, 1 | 124 | 3634 | 5275 |
| Без изменений, 2 | 163 | 2537 | 4014 |
| Без изменений, 3 | 119 | 2419 | 3986 |
| Изменен leaf C-маркер | 530 | 1724 | 3747 |
| Исходный C-маркер восстановлен | 444 | 2568 | 4226 |
| Изменен default строкового поля схемы | 587 | 1849 | 3664 |
| Исходная схема восстановлена | 600 | 1710 | 3775 |
| Изменен перевод с прежним набором символов | 924 | 2565 | 5091 |
| Исходный перевод восстановлен, со скриншотом | 832 | 2438 | 5006 |

В трех no-op логах Ninja сообщает `no work to do`. C-проба пересобрала одну
единицу трансляции и перелинковала EXE. Схема вызвала генерацию и компиляцию
четырех C-файлов. SHA-256 графического пака одинаков во всех девяти прогонах.
Изменение текста не запускало паковку графики. Набор шрифтовых символов также
не изменился; добавление отсутствующего символа потребовало бы отдельной проверки.

Это опровергает первоначальное общее предположение «обычная правка текста или
баланса заставляет заново обрабатывать графику». Баланс в реальных играх может
жить в C, Lua или генерируемых таблицах; для всех этих представлений одинаковый
эффект не измерялся. Изменение default схемы не выдается за замер игрового баланса.

Результаты: `tmp/studio-refresh/native-research/runs.jsonl`, отдельные compile
логи в том же каталоге, `tmp/captures/iterate.png`. На скриншоте виден отдельный
стенд общих фич, а не пустой стартер. Точные C/schema маркеры были получены из
работающего процесса во всех девяти циклах.

Механика соответствует [модели зависимостей Ninja](https://ninja-build.org/manual.html#_conceptual_overview):
сборщик выбирает устаревшие выходы по графу зависимостей. [CMake CONFIGURE_DEPENDS](https://cmake.org/cmake/help/v3.31/command/file.html#glob)
добавляет проверку glob-набора при запуске сборки; наличие такой проверки само
по себе не означает повторную компиляцию или паковку.

## 2. Подтвержденный дефект подключения DevAPI

В [connect_existing](../runtime_automation/devapi_client.py) внешний `timeout`
проверяется вокруг цикла, но одна попытка создает `DevApiClient(timeout=1.0)`.
После неудачи следует безусловный `sleep(0.2)`. `running_game` перед запуском
нового процесса вызывает эту функцию с `timeout=0.1`, проверяя занятость порта.
Результат: запрос на 100 мс может ждать примерно 1200 мс еще до создания игры.

Трассировка первой текущей пробы: socket timeout 1015 мс, prelaunch check
1215 мс; после создания процесса readiness connect занял еще 1730 мс.
Это измеренный дефект общего deadline, а не установленная задержка Avast.
Согласно [контракту Python socket](https://docs.python.org/3.12/library/socket.html#socket.create_connection),
connect timeout задается самой операции подключения; внешний цикл сам по себе
не ограничивает продолжительность уже начатой операции.

| Запуск | Текущий precheck, мс | Precheck прототипа, мс | Текущий запуск до client-ready, мс | Прототип, мс |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1215 | 117 | 2950 | 730 |
| 2 | 1207 | 121 | 2439 | 655 |
| 3 | 1205 | 105 | 1726 | 935 |

После readiness оба варианта выполняли одинаковые `endpoints` и
`game.iteration.proof`; точные исходные C/schema значения совпали. Время этих
RPC оставалось примерно 124–162 мс. Полный запуск с proof и завершением занял
2291–3643 мс у текущего клиента и 1139–1534 мс у прототипа.

Прототип ограничивал каждую connect-попытку 50 мс и оставшимся общим временем,
коротко ждал между попытками и сохранял отдельный request timeout 5 с.
Поэтому весь выигрыш нельзя приписывать только precheck: менялось и ожидание
после создания процесса. Чередование уменьшает, но не исключает влияние прогрева.

Направление исправления: монотонный deadline, connect timeout не больше остатка,
ожидание не больше остатка; request timeout и диагностику умершего дочернего
процесса сохранить. Затем отдельно проверить занятой порт, медленный старт,
немедленный exit и отсутствие слушателя. Текущий тест в
`devapi_client_test.py` закрепляет именно `timeout=1.0`, поэтому его следует
заменить тестом deadline-контракта. Это ограниченная задача владельца Runtime
Automation; движок и архитектура игр для нее не меняются.

Доказательства: `native-research/launch-runs.jsonl` и
`tmp/studio-refresh/research_launch.py`.

## 3. Штатные проверки игр: различаются поколения инструментов

| Потребитель и проба | Весь `test --only`, мс | Деталь |
| --- | ---: | --- |
| A, первый прогон | 6612 | Native build 3649 мс, включая 196 build steps |
| A, теплый 1 | 2813 | Node suite 1563, CMake build 132, три CTest процесса 810, Git 278 мс |
| A, теплый 2 | 3949 | Node suite 1650, CMake build 359, три CTest процесса 1584, Git 310 мс |
| B, первый прогон | 4528 | Более новая обвязка с отчетом каждого subprocess |
| B, теплый 1 | 2026 | Focused native путь, без общей Node suite |
| B, теплый 2 | 2518 | Focused native путь, без общей Node suite |

У A `--only` сужает CTest, но перед ним безусловно запускается вся Node suite
игровых tools. В частности проверяются web build/package инструменты при выборе
одного нативного теста. На двух теплых пробах это 1,56–1,65 с.

В новом стартере и общем consumer этот fast path уже исправлен. У B свой
современный runner также пропускает Node suite для точечного выбора. У другой
игры default native core и tooling scope уже разделены. Поэтому исправление
следует переносить только в потребителей со старым поведением, сохраняя проверки
по умолчанию. Еще один глобальный runner для этого не нужен.

Эти два теста проверяют разные контракты. A дополнительно строит игровой target,
B в точечном режиме строит только target выбранного теста. Их полные времена
нельзя выдавать за сравнение одной и той же сборки или за доказательство свежей
игровой картинки. Три вызова CTest и проверка Git имеют видимую стоимость,
но их удаление без проверки порядка discovery/build/label validation не обосновано.

Результаты: `native-research/legacy-focused-{1,2,3}.json`,
`modern-focused-{1,2,3}.json`, `cli-summary.json`; имена и пути игр остаются
только в этих игнорируемых локальных материалах.

## 4. Готовность старых игр важнее ускорения их кеша

В текущем checkout `doctor` прошел у 5 из 11 основных игр. Шесть основных игр
остановились на `engine dependency revision mismatch`. С учетом производных
копий получилось 6 успешных и 8 остановленных проверок из 14. Успешные проверки
заняли 379–557 мс; остановленные — 119–134 мс. В этих случаях до сборки дело
вообще не доходит.

Проверка корректно защищает закрепленную зависимость. Нельзя заменить revision
в manifest текущим HEAD без проверки совместимости. Часть игр имеет собственное
дерево движка/фич, часть берет его из Studio; единый текущий Studio checkout
не равен совместимому окружению всех старых игр.

Нужен явный выбор для игры, которую действительно возобновляют: совместимое
окружение с ее закрепленными зависимостями либо проверяемая миграция на текущие.
Сначала проверить, покрывает ли существующий workspace workflow такой случай.
Это задача готовности среды; автоматическая массовая миграция всех архивных
прототипов из результатов исследования не следует.

Полный Studio gate намеренно не запускает private games. Его прежний PASS
не означает, что `doctor`, build и gameplay каждой старой игры проходят.
Исходная граница проверки:
[verifyDependencySources](../game_tools/package_web.mjs).

## 5. У локализации есть точный, но меньший источник пересборок

[render_header](../../features/localization/scripts/loc.py) вставляет переводы
через `Entry.comment()` рядом с enum и объявлениями функций. Правка текста
меняет комментарии в `loc_strings.gen.h`, хотя C API прежний. После этого
сборщик правильно перекомпилирует все включающие измененный header файлы.

Офлайн-сравнение двух сгенерированных вариантов подтвердило одновременно:

- Header различается, но после удаления C-комментариев его код идентичен.
- Реализация строковой таблицы различается.
- Заголовок набора символов идентичен.
- Реальный build с этой правкой скомпилировал 9 C-файлов и перелинковал EXE;
  графический пак остался побайтно прежним.

Это не ошибка Ninja и не повторная обработка графики. Причина — смешение
стабильного API и меняющихся переводов в одном header. Генератор уже использует
`write_if_changed`, поэтому совет просто добавить такую проверку был бы ошибочным.

Наличие переводов в header — документированный grep-контракт
[localization README](../../features/localization/README.md) и существующий тест.
Возможная оптимизация: сохранить grep-данные отдельным выходом, а API header
менять только при изменении ключей/сигнатур. Это требует пересмотра контракта
feature. Текущая генерация встречается у общего consumer и 10 private consumers;
это не 10 независимых игр, и часть исходников имеет общую историю.

При build всего 0,92 с на стенде срочность ниже, чем у подключения DevAPI.
Сэкономленное время после изменения генератора еще не измерено; цифру ускорения
для других игр обещать нельзя. Материал: `localization-header-proof.json` и
`loc-existing-charset-3-compile.log` в каталоге исследования.

## 6. Обычная итерация и формальные доказательства стоят по-разному

Текущий полный native-capture preflight плюс final validation общего consumer
занял 10 495 мс. Фазы: source fingerprint 4527 мс, no-op build 122 мс,
source fingerprint 2859 мс, final source fingerprint 2974 мс. Это замер без
самой записи видео. Прежние 119,7 с были другим запуском со сборкой и
конкурирующей нагрузкой; переносить это число на каждую итерацию нельзя.

Три source/checkpoint наблюдения закрывают разные интервалы. Их стоимость
подтверждена, но из этого не следует, что их можно удалить. Для обыкновенного
взаимодействия с неизмененной игрой уже есть attach/reuse. Он не подтверждает,
что запущенный EXE содержит только что измененный код. Скриншот работающего
процесса и source-bound capture proof должны оставаться разными утверждениями.

Ранее измеренный Studio full gate 224,2 с — приемка общих модулей, а commit
privacy scan — отдельный этап. Они не являются нативной сборкой. Политика
focused checks при правках и full на CI/приемке уже закреплена; предлагать ее
как новую еще не реализованную возможность неверно.

Сохранение обычных guard и отделение их от повседневного запуска предпочтительнее
нового persistent freshness cache без доказанного контракта инвалидации.

## 7. Что показывают реальные сессии агентов

Свежий профиль окна 2026-10-11 — 2026-10-18 содержит 794 Codex и 5 Claude
session files, 65 784 наблюдаемых tool records и около 192,94 MB сохраненного
вывода. Категория research — 108,95 MB, validation — 14,73 MB, mixed batches —
22,46 MB. Большой объем исследования подтверждается; его бесполезность и
экономия времени от конкретного изменения этим еще не доказаны.

Суммы длительностей параллельных инструментов и дочерних агентов нельзя складывать
в человеческое ожидание. Mixed batch не позволяет честно приписать общий вывод
или длительность одной вложенной команде. Счетчик truncated tokens — метрика
парсера, не счет за API. Сравнивать продуктивность моделей по этим категориям
без одинаковых задач нельзя.

Существующие правила уже требуют ограниченных чтений и коротких доказательств.
Нужна проверка их исполнения на конкретных повторяющихся командах, а не еще
один общий документ с теми же правилами. В этом исследовании особенно полезным
оказался запрос контрпримеров: он выявил готовый dev-loop и уже исправленный
долгий тест, которые первоначальная сводка ошибочно считала отсутствующими.

Профиль: `tmp/studio-refresh/research-iterations-7d.json`. Выборки истории игр
сохраняют собственные ограничения; весь исторический Git и все сессии каждой
игры полностью не перечитывались.

## 8. Предложения, которые снимаются или откладываются

| Прежнее предположение | Проверка текущей реальности | Решение |
| --- | --- | --- |
| Нужен новый watcher для быстрой разработки | У двух игр есть `dev` с наблюдением, native rebuild и restart client/room | Сначала использовать существующий; перенос возможен только для конкретного нужного потребителя |
| Нужен web-сервер в основном цикле | Нативная сборка уже быстрее в измеренных source-edit сценариях; browser нужен для собственных контрактов | Основной цикл native; web по изменению браузерной части и перед web-релизом |
| Надо переделать кеш сборки | No-op 119–163 мс, C edit 530 мс | Не переделывать |
| Каждая правка текста перестраивает графику | Pack hash не изменился во всех пробах | Снять; отдельно решать header fan-out |
| Обычный тест все еще занимает исторические 122,8 с | Текущий room-session тест в `net`, default `core`; старый источник заменен | Историческую проблему считать снятой из core; текущий net runtime не измерен |
| Нативный CLI отсутствует во всех играх | У части игр есть `dev`, у части CLI по-прежнему web-oriented | Не обобщать; сохранять различия и доказанную игровую политику |
| Нужно заново сделать сценарии и DevAPI | Есть shared client, scene feature и игровые semantic/state сценарии | Не создавать параллельный механизм; удобство проверять на конкретном сценарии |
| Все tooling можно сразу вынести в один пакет | Есть разные engine roots, build targets, сетевые режимы, proof и release policy | Только поэтапный перенос общего контракта; одна папка сама по себе не ускоряет работу |

Исторический медленный room-session сейчас использует отдельный `net` tier и
60-секундный сетевой benchmark. Его таймаут не является доказательством текущей
длительности. Existing native dev-loop делает restart, а не live reload данных.
Сделать hot reload технически можно обсуждать отдельно, но измеренная цена
компиляции пока не доказывает приоритет такой переделки.

## Приоритет следующих изменений

1. Исправить timeout/deadline в общем DevAPI connect. Есть воспроизведение,
   точная причина и прототип с одинаковым semantic proof. Изменение ограничено
   клиентом и его тестами.
2. При возобновлении конкретной старой игры явно разрешить engine compatibility.
   Не менять pins автоматически. Отчет о готовности должен отличать несовпадение
   зависимостей от build failure и от долгой сборки.
3. Перенести уже проверенный focused-test контракт в нужные старые game CLI.
   На измеренном потребителе можно убрать обязательную Node suite из явного
   native `--only`, оставив ее в обычной проверке. Сначала проверить его game-owned
   тесты и режимы; общая замена всех `game.mjs` не требуется.
4. Рассмотреть стабильный localization API header с отдельным grep output.
   Сначала согласовать сохранение поискового контракта, затем измерить измененный
   текст на более крупном потребителе. По текущим цифрам это меньшая оптимизация.
5. Сверить README и runbook с текущим native workflow. В частности старый абзац
   Runtime Automation направлял `iterate.py` в template, хотя код уже работает
   с независимым feature consumer. Исправление документации дешевле нового runner.

Не добавлять автоматически новые Taskboard items и не выдавать эти направления
за выполненные изменения. Не менять антивирус, не добавлять исключения, не
ослаблять release/capture proof и не редактировать движок ради этого исследования.

## Реализация согласованных изменений

После уточнения лида старые игры считаются неактивными для текущей работы.
Их несовпадающие engine pins не являются блокировкой общей Studio; миграция
движка не выполнялась, статусы игр автоматически не менялись.

Исправлены только подтвержденные направления:

- Общий DevAPI-клиент соблюдает монотонный connection deadline при connect и
  retry; короткие loopback-пробы не меняют request timeout. Регрессии проверяют
  общий бюджет, отложенную готовность, нулевой бюджет, реальный занятый порт и
  диагностику завершившегося процесса. Набор клиента: 32/32 PASS.
  Весь Python-набор Runtime Automation после интеграции: 197/197 PASS за 2,74 с.
- Девять старых игровых CLI пропускают общую Node suite только при явном
  `--only`. Dependency checks, default/core, `--tier`, `--all` и `verify`
  сохранены. Их tool suites: 109 PASS, один существующий skip fixture с
  условием `requires the studio checkout`. Новые focused-регрессии сначала
  падали на всех девяти потребителях.
- Localization `1.3.0` выносит прежний key-to-text grep output в
  `loc_strings.gen.txt`. API header, charset и key index сохраняют bytes/mtime
  при правке текста; таблица строк обновляется. Обновлены контракт, INSTALL,
  общий consumer и pins пяти уже совместимых shared consumers. Старые engine
  pins сохранены. Генератор: 53/53 PASS; native `test_loc_e2e` и
  `loc_generator_test`: 2/2 PASS. Контракты: 17 modules, 2 pointers PASS.

Проверенные изменения общих модулей и игровые адаптеры зафиксированы отдельными
коммитами; в игровых репозиториях включены только эти scoped files, без остальных
изменений рабочих копий. Независимые code reviews завершились без P1/P2.

пробе остались прежними; поисковый файл содержал новый текст.

Один обратный прогон со скриншотом занял 38,2 с при сумме измеренных фаз около
3,4 с. Неатрибутированный остаток нельзя объявить исправленным или списать на

закрытие клиента 0,13 мс, остановка процесса 289 мс. Выброс не повторился;
его причина остается неизвестной. Числа таблицы не являются гарантией p99.

Повторный `doctor` сохранил тот же набор: 5/11 основных игр и одна производная
копия проходят; остальные 8 рабочих копий останавливаются на прежнем engine
revision mismatch. Новых несовместимостей feature pins у ранее совместимых
потребителей не осталось. Полный Studio gate не повторялся: проверены измененные
контракты и реальный нативный цикл.
