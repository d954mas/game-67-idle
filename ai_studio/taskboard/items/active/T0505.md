## What

The two online games back up their metaserver Postgres with different code: one runs deploy/backup.sh in a backup.Dockerfile container from compose, the other deploy/speed-backup.py. Both games run the same features/metaserver schema. One backup implementation belongs next to features/metaserver; each game keeps only its config (paths, retention, schedule). The change reaches production at each game's next release.

## Done when

- [ ] One backup tool in features/metaserver with tests (dump, retention, restore check); both games use it and their own implementations are gone.
- [ ] A local Postgres with the metaserver schema: backup then restore into a fresh database yields the same rows.
- [ ] Each game's release flow and README name the new tool; the next release of each game runs it on production and a restore check passes there.
