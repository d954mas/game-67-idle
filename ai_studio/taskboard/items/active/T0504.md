## What

On Windows a process that used the curl WebSocket client exits slowly after main returns: a probe (server + N loopback clients, each destroyed) measured ~1 s exit for 1 client, ~1.6 s for 5, ~5 s for 20; the network-core roundtrip test spends ~25 s after main. A connect to a closed port also takes ~2 s (Windows SYN retries) and its detached thread holds the exit. Root cause not yet located (candidates: curl easy cleanup in the worker thread, detached connecting threads, Winsock teardown).

## Done when

- [ ] Root cause found with a reproduction (exit time vs client count).
- [ ] Exit after destroying clients takes under 100 ms regardless of count, or the remaining cost is explained.
- [ ] network-core roundtrip test wall time drops accordingly.
