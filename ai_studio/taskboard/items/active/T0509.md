## What

net_ws_server's service(timeout_ms) can return well after its timeout (5 ms -> ~15 ms seen on Windows): the uSockets loop cannot bound its wait and work runs outside it. The header was softened during the roundtrip-pacing work; a room's tick needs a bounded service. Seen on Windows only; production rooms run on Linux, so first measure it there: if Linux is within bound, this is a dev-machine issue only.

## Done when

- [ ] service() returns no later than its deadline plus a measured bound, or the room tick no longer depends on it (decided after research).
- [ ] A test measures the overshoot on the default and a 1 ms timer resolution.
- [ ] The header states the real contract.
