## Goal

Сегодня, чтобы увидеть состояние игры, лид ходит по папкам: билды в
`build/<config>/`, паки бинарные и нечитаемые, каталог предметов в отдельном
Items Workbench, канвасы в канвас-редакторе, скрины прогонов теряются в
`capture/`. Единой точки «открыл игру — увидел всё» нет.

Эпик добавляет в Studio Shell страницу игры: со home открывается любая игра
(публичная или приватная), и на одной странице видно её identity и дизайн-доки,
билд-конфиги с артефактами и размерами, содержимое каждого ntpack вплоть до
просмотра текстур, атласов и глифов шрифтов, баланс (Items Workbench),
канвас-проекты игры, state-схемы и список captures по дате.

Поверхность локальная и read-only: страница показывает и ведёт в существующие
тулзы, но не запускает сборки и не правит данные сама.

## In scope

- Список игр на home: все игры через workspace-резолвер, включая приватные.
- Страница игры с шапкой-обзором: identity из `game.json`, ссылки на GDD и
  `design/`, проект игры на таскборде, галерею с фильтром игры.
- Раздел «Билды»: конфиги `build/<config>/` со свежестью, артефактами и
  размерами; `release/`; web-билд с размером raw/gz; клик по паку ведёт в
  пак-инспектор.
- Пак-инспектор ntpack: таблица записей (имя, тип, размер raw/gz, формат,
  дубликаты, сводка по типам); текстуры и атласы открываются глазами
  (KTX2 → PNG, атласы с сеткой регионов); шрифты — атлас глифов и чарсет;
  остальные типы — текстом.
- Раздел «Баланс»: Items Workbench становится частью страницы игры.
- Раздел «Канвасы»: список канвас-проектов игры с дип-линками в канвас-редактор
  на сторе игры.
- Раздел «State-схемы»: читаемый список схем состояния игры.
- Раздел «Captures»: файлы `capture/` списком по дате с превью и путём.
- Галерея (Asset Viewer) показывает приватные игры по умолчанию.

## Out of scope

- Действия: запуск сборки, запуск игры, открытие папок с сервера.
- Правка данных со страницы игры (кроме уже существующего Apply-контура самого
  Items Workbench).
- История размеров билдов по коммитам.
- Экономические симуляции и прогрессия поверх баланса.
- Прослушивание аудио и просмотр мешей в пак-инспекторе.
- Публичный шаринг страницы: nt-app-tunnel выставит данные приватной игры,
  это осознанный отдельный шаг лида, не часть эпика.

## Implementation decisions

- Форм-фактор: новая страница Studio Shell, роут `/game/<id>` плюс список игр
  на home; переиспользует общий сайдбар, стили и сервер оболочки.
- Игры резолвятся через workspace-каталог (`workspace/games.mjs`), без
  сканирования папок наугад; приватные игры видимы — поверхность локальная.
- Движок read-only: JSON о содержимом ntpack получаем на стороне студии —
  собственный парсер формата или разбор текстового вывода `nt_builder_dump`;
  правок движка эпик не требует.
- Просмотр текстур: транскод KTX2 (ETC1S/UASTC) в PNG на стороне студии,
  способ (basis-транскодер в браузере или python-тулза) выбирается ресёрчем в
  первом тикете про превью; результаты кэшируются во временной папке.
- Items Workbench и канвас уже per-game (items CLI с `--project-root`,
  канвас-стор `<game>/.ai_studio/canvas/projects`) — страница игры их
  встраивает/линкует, не дублирует.
- Дефолт галереи меняется с «приватные скрыты» на «показывать все»;
  существующий резолвер `game:<id>` остаётся механизмом доступа.
- Порядок срезов: скелет страницы + билды → пак-инспектор текстом → превью
  текстур/атласов/глифов → переезд Items Workbench, канвас-списки,
  галерея-дефолт. Каждый срез полезен сам по себе.

## Testing decisions

- HTTP-шов сервера Studio Shell: node-тесты роутов и JSON-API страницы игры
  (список игр, сводка билдов, дамп пака, captures, схемы) — прямое продолжение
  существующих тестов `studio_shell`.
- Модуль пак-парсера: юнит-тесты «ntpack → JSON» на маленьком фикстур-паке,
  собранном билдером; внешнее поведение (записи, размеры, типы), не внутренности.
- Транскод текстур: тест «KTX2 → PNG» на фикстуре — валидность и размеры
  результата.
- Браузерный UI тонкий: приёмка глазами лида (скрин достигает направления),
  browser-автотестов нет.
