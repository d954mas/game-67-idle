## Goal

Online games each own a server, built from shared libraries: the library owns mechanism (transport, tickets, seat reservation, room shell, tick loop, delta coder, migrations, fleet, observability), the game registers content (field tables, op-code handlers, lifecycle callbacks, migration steps). Un-fork the two live multiplayer games without a big-bang rewrite. Research: `ai_studio/game_design/knowledge_base/knowledge/online_server_stack.md`.

## In scope

- Drift list, meta-kit (Go packages), three-part handshake version, room-host agent (C), room-runtime inversion, net-client, net-tools.
- Extract only what both live games already share; every step proven by `live_games.mjs` on both games.

## Out of scope

- Engine changes.
- Kubernetes/Agones; plain VMs stay the default behind an allocator interface.
- Abstractions for a hypothetical third game.
