## Goal

Each online game owns its server, assembled from shared source: the mechanisms (seat booking, HMAC tickets, room registry and drain, reconnect ladder, protocol hash) already exist in both live multiplayer games; the work is to stop keeping them as two copies, with no new mechanism. Plan reviewed by a subagent and Codex; research: `ai_studio/game_design/knowledge_base/knowledge/online_server_stack.md`.

## In scope

- `features/metaserver`: Go library from the existing code, including the shared pick+book query; each game keeps its own `main.go`, handlers and later its own migrations.
- `features/online-room`: the game-independent C files only.
- Missing fix ports between the two games (cards in the game stores).
- No real players yet: databases, rooms, migrations and ticket generations may be reset instead of migrated.

## Out of scope

- Runtime registries, hook registries, relevance callbacks, TTL reservations, hosting/allocator interfaces, content-revision axis, net-tools: speculative until a game needs them.
- Room loop, authority, sim, prediction, wire schema, report/perf and profile savers stay game code.
- Engine changes except through an engine issue/PR.
